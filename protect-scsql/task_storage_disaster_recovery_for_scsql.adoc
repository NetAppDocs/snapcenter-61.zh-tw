= SnapCenter Plug-in for SQL Server 的儲存災難復原 (DR)
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
您可以透過在「全域設定」頁面中啟用儲存的 DR 模式來還原用於 SQL Server 儲存的SnapCenter插件。

.開始之前
* 確保插件處於維護模式。
* 中斷SnapMirror/ SnapVault關係。link:https://docs.netapp.com/ontap-9/topic/com.netapp.doc.onc-sm-help-950/GUID-8A3F828F-CD3D-48E8-A171-393581FEB2ED.html["中斷SnapMirror關係"]
* 將從屬磁碟的 LUN 連接到具有相同磁碟機號碼的主機。
* 確保所有磁碟都使用 DR 之前使用的相同磁碟機號碼進行連接。
* 重新啟動 MSSQL 伺服器服務。
* 確保 SQL 資源重新連線。


.關於此任務
VMDK 和 RDM 配置不支援災難復原 (DR)。

.步驟
. 在「設定」頁面中，導覽至「*設定*」>「*全域設定*」>「*災難復原*」。
. 選擇“啟用災難復原”。
. 按一下“*應用*”。
. 按一下「*監控*」>「*作業*」來驗證 DR 作業是否已啟用。


.完成後
* 如果故障轉移後建立了新的資料庫，則資料庫將處於非 DR 模式。
+
新的資料庫將像故障轉移之前一樣繼續運作。

* 在 DR 模式下建立的新備份將在拓樸頁面中的SnapMirror或SnapVault （輔助）下列出。
+
新備份旁邊會顯示一個「i」圖標，表示這些備份是在 DR 模式期間建立的。

* 您可以使用 UI 或以下 cmdlet 刪除故障轉移期間建立的 SQL Server 備份的SnapCenter插件： `Remove-SmBackup`
* 故障轉移後，如果您希望某些資源處於非 DR 模式，請使用下列 cmdlet： `Remove-SmResourceDRMode`
+
更多資訊請參閱 https://docs.netapp.com/us-en/snapcenter-cmdlets/index.html["SnapCenter軟體 Cmdlet 參考指南"^]。

* SnapCenter Server 將管理處於 DR 或非 DR 模式的單一儲存資源（SQL 資料庫），但不管理處於 DR 模式或非 DR 模式的儲存資源的資源群組。

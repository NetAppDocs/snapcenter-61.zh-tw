= 確定資源是否可用於備份
:allow-uri-read: 
:icons: font
:imagesdir: ../media/


[role="lead"]
資源是由您安裝的外掛程式維護的資料庫、應用程式執行個體、可用性群組和類似元件。您可以將這些資源新增至資源組中，以便執行資料保護作業，但首先必須確定您有哪些可用資源。確定可用資源也可以驗證插件安裝是否已成功完成。

.開始之前
* 您必須已經完成安裝SnapCenter Server、新增主機、建立儲存系統連線和新增憑證等任務。
* 要發現 Microsoft SQL 資料庫，應滿足以下條件之一。
+
** 用於將插件主機新增至SnapCenter Server 的使用者應具有 Microsoft SQL Server 上所需的權限（sysadmin）。
** 如果不符合上述條件，則應在SnapCenter伺服器中設定在 Microsoft SQL Server 上具有所需權限（sysadmin）的使用者。使用者應在 Microsoft SQL Server 執行個體層級進行配置，並且可以是 SQL 或 Windows 使用者。


* 若要發現 Windows 群集中的 Microsoft SQL 資料庫，必須解除故障轉移群集執行個體 (FCI) TCP/IP 連接埠的封鎖。
* 如果資料庫駐留在 VMware RDM LUN 或 VMDK 上，則必須部署SnapCenter Plug-in for VMware vSphere並向SnapCenter註冊外掛程式。
+
有關詳細信息，請參閱 https://docs.netapp.com/us-en/sc-plugin-vmware-vsphere/scpivs44_deploy_snapcenter_plug-in_for_vmware_vsphere.html["SnapCenter Plug-in for VMware vSphere"^]

* 如果主機新增了 gMSA，且 gMSA 具有登入和系統管理員權限，則 gMSA 將用於連線到 SQL 實例。


.關於此任務
當「詳細資料」頁面中的「*整體狀態*」選項設定為「無法用於備份」時，您無法備份資料庫。當下列任一情況為真時，「*總體狀態*」選項將設定為「不可用於備份」：

* 資料庫不在NetApp LUN 上。
* 資料庫狀態不正常。
+
當資料庫處於離線、復原、復原待定、可疑等狀態時，它們就不處於正常狀態。

* 資料庫權限不足。
+
例如，如果使用者僅具有資料庫的檢視權限，則無法識別資料庫的檔案和屬性，因此無法備份。




NOTE: 如果您在 SQL Server 標準版上具有可用性群組配置，則SnapCenter只能備份主資料庫。

.步驟
. 在左側導覽窗格中，按一下“*資源*”，然後從清單中選擇適當的外掛程式。
. 在資源頁面中，從*視圖*下拉清單中選擇*資料庫*、*實例*或*可用性群組*。
+
點選image:../media/filter_icon.gif["篩選圖標"]並選擇主機名稱和SQL Server執行個體來過濾資源。然後您可以點擊image:../media/filter_icon.gif["篩選圖標"]關閉篩選器窗格。

. 按一下“刷新資源”。
+
新新增、重新命名或刪除的資源將更新至SnapCenter伺服器清單。

+

IMPORTANT: 如果資料庫在SnapCenter之外重新命名，則必須刷新資源。

+
資源與資源類型、主機或叢集名稱、相關資源群組、備份類型、政策和總體狀態等資訊一起顯示。

+
** 如果資料庫位於非NetApp儲存上， `Not available for backup`顯示在*總體狀態*列中。
+
您無法對非NetApp儲存裝置上的資料庫執行資料保護操作。

** 如果資料庫位於NetApp儲存空間且未受保護， `Not protected`顯示在*總體狀態*列中。
** 如果資料庫位於NetApp儲存系統上並受到保護，則使用者介面顯示 `Backup not run`*總體狀態* 列中的消息。
** 如果資料庫位於NetApp儲存系統上並受到保護，並且觸發了資料庫備份，則使用者介面會顯示 `Backup succeeded`*總體狀態* 列中的消息。





NOTE: 如果您在設定憑證時啟用了 SQL 驗證，則發現的執行個體或資料庫將顯示紅色掛鎖圖示。如果出現掛鎖圖標，則必須指定實例或資料庫憑證才能成功將實例或資料庫新增至資源組。

. SnapCenter管理員將資源指派給 RBAC 使用者後，RBAC 使用者必須登入並點選 *刷新資源* 才能查看資源的最新 *整體狀態*。
